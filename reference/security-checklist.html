Agent 安全与权限清单

先画信任边界，再写策略；检测是辅助，授权在边界。

配合 Lesson 0016 打印友好 设计 / review / 红队

这份清单不按“OWASP 条目”组织，而按一次真实的安全 review 的顺序： 先列资产、入口、出口；再用 Rule of Two 判断设计；然后在工具边界逐项 检查能力、参数、污点、出口、审批、沙箱与审计；最后用攻击语料和门禁证明。

01威胁建模

问题要写下来例子
资产Agent 能接触到的、值钱的东西私有仓库、生产日志、客户数据、SSH key、云元数据、发布权限
入口哪些输入是攻击者可写的issue / PR 评论、repo 文件、日志、网页、邮件、工具描述、工具结果
出口数据能从哪里离开或造成副作用HTTP、DNS、图片 URL、链接预览、shell、文件写、PR、评论、webhook、日志
信任边界哪一行代码/哪一个调用点负责检查tool gateway、MCP host、network proxy、secret broker、approval service
攻击者目标读取、外泄、写入、删除、提权、绕过审批把 SSH key 贴到 issue；把 secret 放进图片 URL；向 main 开 PR
一句话

信任边界不在模型里，在工具边界上。模型可以提议动作，不能授予自己能力。

02Rule of Two 快速判断

单个 session 最多同时具备三项中的两项；三项齐备时必须有人类监督、 可靠验证或干净 session。三项是：

ABC
处理不可信输入 访问敏感系统 / 私有数据 改变状态 / 对外通信
issue、网页、日志、邮件、工具结果 私有仓库、客户记录、生产 API、凭据 发消息、开 PR、写库、HTTP、图片加载
配置允许禁止
A+B只读分析、总结、检索写、发消息、任意外网
A+C沙箱里的公开内容研究私有数据、生产凭据
B+C可信输入驱动的内部操作直接读取不可信外部内容
A+B+C仅限人工监督 / 可靠验证 / 拆分 session自主运行

Rule of Two 是启发式，不是证明；“A+C” 只是较低风险，不是安全。 还要单独评估幻觉、资源耗尽、供应链和错误配置。

05发布门禁

security_gate:
  asr:            0 on critical categories
  utility:        >= baseline - allowed_drop
  false_positive: 0 on the golden benign set
  secret_leaks:   0
  approval:       within budget; no rubber-stamp metrics
  audit:          complete; no raw secrets
  attribution:    every attack has a blocking layer
  red_team:       adaptive pass completed before launch

不要只看 ASR。拒绝一切的 Agent 可以拿 ASR 0，但 utility 也是 0。 至少同时报 ASR、utility、误杀、审批摩擦、泄漏与 layer 归因。
