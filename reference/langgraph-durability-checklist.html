LangGraph 持久化与审批清单

checkpoint 在 super-step 边界，interrupt 是持久化的暂停，stream 是观察面。

首次建立 2026-11-04 配套 Lesson 0009 Checkpoint · Interrupt · Streaming · Postgres 可打印

这张清单只回答一个问题：当 Agent 要跨进程、等人工、再恢复时，哪些地方最容易出错？ 先把心智模型压成三句话，再按 API、规则、失败模式逐项检查。

01三句话心智模型

checkpointt = snapshot(statet, pending_taskst)
  1. checkpoint 在 super-step 边界写：一轮节点跑完、增量按 reducer 合并之后，框架才落盘；不是每个节点、每行代码都写。
  2. resume 重放未完成的 super-step：已完成节点跳过；中断/失败的节点从函数第一行重跑，不是从 interrupt() 那一行继续。
  3. 外部副作用不在 checkpoint 事务里：写操作必须带幂等键，或放进 outbox / 唯一约束，否则 resume 会重复执行。
最容易犯的错

把“checkpoint 已保存”当成“外部动作已提交”。两者之间没有分布式事务； 在“外部调用成功、节点返回之前”崩溃，是最典型的重复执行窗口。

02最小骨架

import sqlite3
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.types import Command, interrupt

conn = sqlite3.connect("checkpoints.db", check_same_thread=False)
graph = builder.compile(checkpointer=SqliteSaver(conn))

config = {"configurable": {"thread_id": "incident-42"}}

# 1) 运行到 interrupt 并暂停
result = graph.invoke(initial_state(), config, durability="sync")
pending = result["__interrupt__"][0]
print(pending.value)

# 2) 同一个 thread_id，恢复
result = graph.invoke(
    Command(resume={"approved": True, "approver": "alice", "approval_id": "APR-7"}),
    config,
    durability="sync",
)

# 3) 检查暂停点
snapshot = graph.get_state(config)
snapshot.next                       # ('approval',)
snapshot.tasks[0].interrupts[0]     # Interrupt(value=..., id=...)

03Checkpoint 检查

Thread

  • thread_id 是恢复键，不是用户 ID
  • resume 必须用同一个 thread_id
  • 新 ID = 新时间线，看不到旧状态
  • Postgres 下 ID 长度 < 255

Checkpointer

  • 测试用 InMemorySaver
  • 本地用 SqliteSaver
  • 生产用 PostgresSaver + setup()
  • 多实例必须共享同一个 checkpoint 库

State

  • 只放可序列化的值
  • 不塞 client、文件句柄、密钥
  • schema 变更要考虑旧 checkpoint
  • 长线程制定保留 / 归档策略

副作用

  • 写工具必须有幂等键
  • 幂等键进外部唯一约束
  • 副作用记录进 state 便于审计
  • 只读工具可以安全重放

04Interrupt 规则速查

规则违反后的表现正确做法
需要 checkpointer + thread_id运行时直接报错compile(checkpointer=...)
resume 用同一个 thread_id重新开始，旧暂停还在把 thread_id 持久化到任务表
节点从第一行重跑interrupt 前的日志/写操作重复前置代码保持纯；副作用带幂等键
一个节点每次只放一个 interrupt循环里 resume 指数级重放state 存当前问题 + 条件边回环
不要 try/except 包 interrupt暂停协议被破坏让异常穿透
并行 interrupt 按 id 配对审批值错配到别的任务Command(resume={id: value})

05Streaming 模式速查

mode事件内容适合注意
values完整 state 快照调试面板每步都推，可能很大
updates{node: 增量}进度、审计、测试同一步的并行更新分开到达
messages(chunk, metadata)逐 token UI子图要 subgraphs=True
customget_stream_writer() 事件业务进度resume 后会重发
debug任务 + checkpoint 细节排查调度输出冗长
checkpoints与 get_state() 同形外部镜像 / 审计需要 checkpointer
v2 事件形状

传 version="v2" 时，每个事件是 {"type": ..., "ns": ..., "data": ...}。 ns 为空表示根图；子图事件带任务路径。多模式流按 type 分支即可。

06Durability 模式

模式写盘时机崩溃窗口适用
sync下一步开始前同步写最小审批、写操作、不可丢任务
async下一步执行时异步写（默认）小大多数在线 Agent
exit只在退出 / 报错 / interrupt 时写最大可整体重跑的批处理

新 thread 用 exit 时，中途崩溃可能让 thread 完全不存在。 需要区分“没接收”和“接收了但丢了”，就在 checkpointer 外先写 outbox / admission 记录。

07Postgres 选修检查

SQLite 证明跨进程；Postgres 证明跨实例。多副本服务必须共享同一个 checkpoint 库， 图本身不需要改，只换 saver。 

import os
from langgraph.checkpoint.postgres import PostgresSaver

with PostgresSaver.from_conn_string(os.environ["DATABASE_URL"]) as saver:
    saver.setup()          # migration; idempotent
    graph = builder.compile(checkpointer=saver)

多线程服务用连接池，不要在请求路径里建表：

from psycopg.rows import dict_row
from psycopg_pool import ConnectionPool
from langgraph.checkpoint.postgres import PostgresSaver

pool = ConnectionPool(
    conninfo=os.environ["DATABASE_URL"],
    min_size=1,
    max_size=10,
    kwargs={"autocommit": True, "prepare_threshold": 0, "row_factory": dict_row},
)
saver = PostgresSaver(pool)
saver.setup()              # once at startup
检查项原因 / 做法
setup() 只跑一次DDL migration；多实例并发建表会抢锁
连接池而非每请求连接避免耗尽 Postgres 的 max_connections
autocommit=TrueCREATE INDEX CONCURRENTLY 需要；官方连接串默认也是
prepare_threshold=0与 PgBouncer / 事务池化兼容
row_factory=dict_rowsaver 读取行时期望字典
thread_id < 255官方长度约束；用 UUID / 业务流水号
一条事故一个 thread不同事故共享时间线会读到彼此状态
删除前导出审计delete_thread 删 checkpoints / blobs / writes
查看底层表

setup() 后会出现 checkpoints、checkpoint_blobs、 checkpoint_writes、checkpoint_migrations 四张表。 select thread_id, count(*) from checkpoints group by 1 能看到每条时间线的 checkpoint 数。

08常见失败与定位

现象最可能的原因处理
resume 后又从头开始thread_id 变了用原来的 ID；检查配置来源
interrupt 直接报错没有 checkpointercompile(checkpointer=...)
恢复后外部动作执行两次节点重跑 + 无幂等键加唯一约束 / 幂等键 / outbox
审批值串到别的任务并行 interrupt 没按 id 配对用 {interrupt_id: value}
进度事件重复resume 重放 interrupt 之前的代码事件带 id，消费端去重
checkpoint 存不进去state 里有不可序列化对象只存原始数据；大对象放外部存储
崩溃后 thread 消失用了 durability="exit"关键路径改 sync；加 admission 记录
时间旅行后状态“变了”以为 update_state 是回滚它是分叉；旧 checkpoint 保留，分支成为最新
