State 是通道，reducer 是合并语义，边是控制流。

首次建立 2026-10-31 配套 Lesson 0008 StateGraph · Reducer · Conditional Edge 可打印

用 StateGraph 写 Agent，大多数 bug 不在模型，而在三件事：state 字段的合并语义写错、 路由函数漏了终止条件、消息协议没有配对。这份清单把它们压成一页，写完图后逐项过一遍。

01State schema 检查

字段设计

  • 每个字段都有明确的合并语义（reducer 或 LastValue）
  • messages 用 add_messages，不要用裸 list
  • 计数器 / 轮数用 operator.add
  • facts、decisions、side_effects 用自定义 reducer
  • answer、phase、stop_reason 可以 LastValue

内容边界

  • 存原始数据与结构化结果，不存格式化后的 prompt
  • prompt 在节点内部组装，不同节点可以复用同一份 state
  • 只存下游需要、且无法从别处推导的值
  • 大块工具输出考虑裁剪或放外部存储

更新方式

  • 节点返回增量字典，不原地修改 state
  • 不返回“完整 state”来绕过 reducer
  • 并行分支写同一字段时，必须有 reducer
  • 每次更新后检查状态是否可序列化

可恢复性

  • state 只含可序列化的值（不塞 client、文件句柄）
  • 副作用记录与幂等键进 state（第 7 课）
  • checkpoint 在节点边界发生，节点粒度影响重跑成本
  • 长任务把 state 版本化，避免 schema 漂移

02Reducer 语义速查

写法合并行为典型用途常见坑
field: TLastValue：新值覆盖旧值answer、phase列表被整体替换，历史丢失
Annotated[list, add_messages]新 id 追加；同 id 更新；支持删除messages以为同 id 会保留两条；需要审计时另设 events
Annotated[int, operator.add]相加rounds、token、retry初始值缺失或未返回增量，计数不动
Annotated[dict, merge_fn]自定义：按 key 合并、冲突标记facts、decisions直接 dict.update 会丢旧值来源
Annotated[list, operator.add]列表拼接events、citations并行顺序不保证；需要排序时加序号字段
默认覆盖不是 bug，是语义

没有 reducer 的字段就是 LastValue。节点返回 {"messages": [msg]} 时， 整个 messages 通道会被这一条消息替换。要么加 reducer，要么在节点里返回完整列表； 前者几乎总是更好的选择。

05停止条件三层

层机制失败表现你要做什么
任务层模型不再返回 tool_calls答非所问prompt、工具、评测
应用层max_rounds / token / 时间 / 成本结构化 stop_reason路由到终止节点，补 SKIPPED ToolMessage
框架层recursion_limitGraphRecursionError兜底；用它排错，不靠它做业务预算
超时与重试

LangGraph 支持节点级 RetryPolicy、异步超时与 error_handler。 默认重试策略不会重试 ValueError / TypeError 这类代码错误； 工具错误应作为 observation 返回，而不是让节点崩溃。

07最小骨架

from typing import Annotated, Any, Dict, List, TypedDict
import operator

from langchain_core.messages import AnyMessage
from langgraph.graph import END, START, StateGraph
from langgraph.graph.message import add_messages

class AgentState(TypedDict):
    messages: Annotated[List[AnyMessage], add_messages]
    rounds: Annotated[int, operator.add]
    tool_events: Annotated[List[Dict[str, Any]], operator.add]
    max_rounds: int
    answer: str
    stop_reason: str

def model_node(state: AgentState) -> Dict[str, Any]:
    response = llm.invoke(state["messages"], registry.schemas())
    return {"messages": [response], "rounds": 1}

def route_after_model(state: AgentState) -> str:
    last = state["messages"][-1]
    calls = getattr(last, "tool_calls", None) or []
    if not calls:
        return "final"
    if state["rounds"] >= state["max_rounds"]:
        return "budget"
    return "tools"

builder = StateGraph(AgentState)
builder.add_node("model", model_node)
builder.add_node("tools", tools_node)
builder.add_node("finalize", finalize_node)
builder.add_node("budget_exceeded", budget_exceeded_node)
builder.add_edge(START, "model")
builder.add_conditional_edges(
    "model",
    route_after_model,
    {"tools": "tools", "final": "finalize", "budget": "budget_exceeded"},
)
builder.add_edge("tools", "model")
builder.add_edge("finalize", END)
builder.add_edge("budget_exceeded", END)
graph = builder.compile()

08调试顺序

  1. 先画图：graph.get_graph().draw_mermaid()，确认节点与边符合预期。
  2. 再看路由：在每个路由函数入口打印 rounds、最后一条消息类型与 tool_calls。
  3. 再看增量：每个节点返回了什么字段？是否只返回了自己改的字段？
  4. 再看 reducer：这个字段是覆盖还是合并？合并结果是否符合预期？
  5. 最后看模型：只有前面都对了，才去怀疑 prompt 或模型。
