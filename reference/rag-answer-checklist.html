RAG 答案与引用清单

检索到了只是开始；让答案可核查，才是终点。

首次建立 2026-10-25 配套 Lesson 0004 重排 · 引用 · 失败归因 可打印

这份清单把 RAG 的后半段压成一页：两阶段检索、引用协议、引用校验阶梯、 七类失败点，以及答案级评测的最小指标。设计或排错时逐项过一遍。

01两阶段检索：先看上限，再调排序

第一阶段（召回）

  • candidate_k 是 15、50 还是 200？延迟预算允许多大？
  • 混合检索是否覆盖了精确标识符与语义改写？
  • candidate_k 的 recall ceiling 是多少？
  • 有没有测过“正确证据在候选集但排第 8”的比例？

第二阶段（重排）

  • 用 cross-encoder API、本地模型，还是 LLM 打分？
  • 重排前后 Recall@k、MRR、nDCG、context chars 各变了多少？
  • 重排超时/失败时，是否降级到第一阶段结果？
  • 重排后的 top-k 顺序是否把最强证据放在开头/结尾？

上下文组装

  • top-k 是否去重？同一文档的多个 chunk 是否挤占预算？
  • 是否带上 doc_id、heading、行号、版本？
  • 是否把最强证据放在中间？小心 lost in the middle。
  • 是否记录每次查询的 context chars/token 成本？

不要做的事

  • 用重排去修“候选集没召回”——修不了。
  • 只看 recall，不看 context cost 与 precision。
  • 把 candidate_k 调到 200 却不看延迟。
  • 用平均分掩盖 semantic / multi-hop 切片的失败。

02引用协议：让引用可校验

03引用校验阶梯

层级检查成本抓什么
1ID 是否存在极低编造来源、引用未提供文档
2quote 是否在来源文本中低改写、引用错段、幻觉 quote
3claim 是否被 quote 蕴含高引用存在但不支持、过度推断、矛盾
4人工抽样审计最高业务判断错误、细微语义偏差

第 1–2 层必须自动化并进 CI；第 3 层用 NLI / LLM judge，需人工校准； 第 4 层按风险抽样，不要用“模型自评”替代。

Quote containment 的盲区

引用真实存在、quote 也在来源里，但结论与 quote 相反——第 2 层会放行。 这类失败只能靠第 3 层。不要把“引用校验通过”等同于“答案正确”。

04七类失败点速查

#失败点典型症状先查什么
FP1Missing Content语料没有答案，系统硬答abstention accuracy；补数据
FP2Missed Top Ranked答案在候选集但不在 top-krecall@k、MRR、rerank
FP3Not in Context召回了但被截断/去重掉context chars、context precision
FP4Not Extracted证据在上下文，模型没抽出来faithfulness、失败轨迹
FP5Wrong FormatJSON/Markdown 格式不符格式合规率、解析失败率
FP6Incorrect Specificity答案太泛或太窄rubric、人工抽样
FP7Incomplete答了一部分，漏了关键步骤checklist coverage

05答案级指标

指标定义抓什么失败
Answer accuracy期望事实出现、禁止表述不出现事实错误、过度推断
Grounded rateID 有效 + quote 可验证 + claim 有引用引用伪造 / 缺失 / 不支持
Citation precision有效 citation / 全部 citation乱引、引用错段
Citation recall有效引用的期望来源 / 期望来源总数多来源漏引
Faithfulness被 context 支持的 claim / 总 claim上下文里没有的结论
Abstention accuracy不可回答用例中正确拒答比例FP1 硬答
Pass rate事实 + 引用 + 来源召回全过端到端可靠性

0620 分钟排错循环

  1. 先分层：正确证据没进候选集（retrieval）？进了但没进 top-k（rerank）？进了但答错/乱引（generation/citation）？
  2. 看 ceiling：candidate_k 的 recall ceiling 是多少？重排后的 recall 是否已经接近它？
  3. 看引用：invalid ID、quote not found、uncited claim、missing source、unsupported claim，分别计数。
  4. 只改一个变量：candidate_k、reranker、prompt、模型、chunking，不要同时动。
  5. 重跑同一套用例：记录 recall、MRR、context chars、grounded、citation precision/recall、abstention。
  6. 保留或回滚：如果 recall 上升但 citation precision 下降，判断这笔交易是否值得。

07最小代码片段

两阶段接口

candidates = retriever.search(query, candidate_k=15)
reranked = rerank(query, candidates, top_n=5)      # cross-encoder / heuristic
sources = build_sources(reranked)                   # [S1] doc_id + heading + lines
answer = generate(query, sources)                   # JSON with citations
check = check_citations(answer, sources)            # IDs / quotes / coverage

引用 JSON

{
  "answer": "根因是 N+1 循环查询 [S1]。",
  "citations": [
    {"source_id": "S1", "quote": "形成 N+1"}
  ]
}

校验三件事

invalid_ids      = cited_ids - source_ids
quote_not_found  = quote not in source.text
uncited_claims   = claims without a citation (or a covering quote)
