RAG 检索清单

设计 chunk、选检索器、读评测报告时，逐项过一遍。

首次建立 2026-10-24 配套 Lesson 0003 设计 · 实现 · 评测 可打印

检索的质量不是“感觉”，而是一组可以逐项检查的工程决策： 语料怎么切、索引怎么建、两路怎么融合、用什么指标证明它没退步。 这份清单不解释概念，只把第 3 课的关键判断压成一页。

01动手前：先把问题定义清楚

语料

  • 总量多少文档 / chunk？增长有多快？
  • 语言与代码占比？有没有表格、图片、PDF？
  • 更新频率？能不能接受小时级延迟？
  • 有没有权限分级？检索结果能不能跨租户？

查询

  • 用户是在问事实、问原因，还是要求跨文档综合？
  • 有多少精确标识符（错误码、类名、配置键）？
  • 有多少口语改写、同义词、跨语言？
  • 延迟预算与上下文预算分别是多少？

答案

  • 回答必须引用出处吗？引用到文档还是行号？
  • 答错与拒答，哪个代价更高？
  • 是否允许“检索不到就说不知道”？
  • 哪些失败必须人工接管？

评测

  • 有没有 20–50 条带证据标签的真实查询？
  • 有没有按 keyword / semantic / multi-hop 切片？
  • 指标是否包含 recall、precision、context cost？
  • 评测集进 CI 了吗？文档改名会不会让它腐烂？

04默认值与调参起点

参数起点什么时候改
chunk size200–500 tokens（事实）/ 512–1024（推理）语义切片太碎，或上下文成本过高
chunk overlap10–20%边界证据频繁丢失；注意重复存储与冗余召回
candidate_k50正确结果总在第 6–10 名，或融合后丢失单路好候选
top-k5–10多跳/跨节查询；同时观察 ctx_chars
RRF k60想让头部排名更尖锐（调小）或更平滑（调大）
BM25 k1 / b1.5 / 0.75词频饱和或长文档偏置明显时小范围试
hybrid alpha0.5（若用加权）精确标识符多则降低 alpha；口语查询多则提高

05指标速查

指标定义适合诊断
Recall@k命中的证据数 / 证据总数，按查询平均该找到的有没有找到
Full@k所有证据都进 top-k 的查询比例多证据 / 多跳任务
MRR@k1 / 第一条命中证据的排名，按查询平均第一条结果是否靠谱
Precisiontop-k 中命中证据的 chunk 比例上下文里有多少噪音
Context charstop-k chunk 的字符数之和token 成本与延迟
nDCG@k带等级的相关性折损累计增益多级相关性排序
Context recall / precisionRagas 用 LLM 判断参考事实覆盖与噪音没有人工证据标签时的替代

黄金集要有“应该拒答”的负例；只测可回答的问题，会把“什么都返回 top-1”的系统误判成高召回。

06失败归因表

你看到的先怀疑先做什么
正确文档完全不在 top-k分词、embedding 不匹配、索引过期用 exact query 测 BM25；检查索引版本与文档是否同步
正确文档在，正确段落不在chunk 边界、chunk 过大/过小看证据是否被切开；试 structure chunker / parent-child
正确段落在第 6–10 名融合权重、candidate_k 太小加大 candidate_k；上 rerank；调 RRF/alpha
keyword 切片满分，semantic 很烂缺语义通道，或 embedding 太弱接 dense；用真实 embedding 重跑；检查 query/document 输入类型
所有切片都平庸chunk 设计或语料解析有问题先人工看 10 个 chunk；修正解析与标题路径
评测集总是 100%标签泄漏或查询太简单加入改写、否定、多跳与负例；用真实工单
改了文档后分数突变评测标签过期把 --validate 放进 CI

0720 分钟调参循环

  1. 固定评测集：先跑一次 baseline，记录 recall / full / mrr / precision / ctx_chars。
  2. 按类型切片：keyword、semantic、mixed、multi-hop，各看一遍。
  3. 挑最差的一类：只改一个变量（chunker、tokenizer、candidate_k、融合权重、embedding）。
  4. 重跑同一套用例：记录变化；不要同时改两个变量。
  5. 看失败轨迹：是没召回、排太低，还是证据被拆开？
  6. 保留或回滚：如果 recall 上升但 ctx_chars 翻倍，判断这笔交易是否值得。

08最小代码片段

BM25 打分

score = 0.0
for term in query_terms:
    if term not in doc_tf:
        continue
    idf = log(1 + (N - df[term] + 0.5) / (df[term] + 0.5))
    freq = doc_tf[term]
    denom = freq + k1 * (1 - b + b * doc_len / avgdl)
    score += idf * freq * (k1 + 1) / denom

scores = {}
for ranking in [bm25_ranking, vector_ranking]:

        scores[chunk_id] = scores.get(chunk_id, 0.0) + 1.0 / (60 + rank)
