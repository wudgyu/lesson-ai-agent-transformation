01System prompt 结构

必须写清

  • 角色与目标：输出给谁、用来做什么
  • 类别/动作定义：包含什么、不包含什么
  • 优先级/严重度定义
  • 不确定性与拒答策略
  • 输出契约：字段、类型、枚举、必填
  • 数据边界：哪些内容只是数据

常见错误

  • “请准确”这类不可执行的愿望
  • 只写类别名，不写边界
  • 把用户输入拼进 system
  • 没有拒答/转人工出口
  • 示例与契约格式不一致
  • prompt 过长，挤占证据预算

02Few-shot 检查

03输出契约检查

检查项问题
字段是否覆盖下游真正需要的字段？
类型bool / number / string 是否明确？
枚举category/priority 是否封闭？
必填缺字段时是报错还是默认值？
额外字段是否允许模型自由添加？通常不允许。
不确定性是否有 needs_human / unknown / refusal？
校验解析成功之后是否做业务校验？
修复校验失败是否反馈错误并有限重试？

05评测检查

指标抓什么
Exact accuracycategory + priority + needs_human 全对
Category / priority accuracy分类与优先级分别错在哪
Schema validity输出能否被程序直接消费
Parse failures有多少输出根本不是 JSON
Prompt tokens上下文预算成本
Refusal accuracy该转人工时是否正确转人工

按类别、优先级、歧义/正常切片；平均分会掩盖某一类系统性失败。

06失败归因表

现象先怀疑先做什么
输出不是 JSON没有输出契约 / 没有 structured outputs加 schema、JSON mode、解析容错
枚举越界枚举没写清 / 示例不一致定义枚举 + few-shot 示例一致
少字段必填没强调 / 没有校验schema required + 校验 + 修复
类别总错在同一类类别定义重叠 / 示例缺失补边界定义与边界示例
全部 needs_human=true拒答策略过保守明确“什么时候不必转人工”
评测分数虚高示例泄漏测试集换示例；保留 holdout
成本太高prompt/示例过长精简定义；用 schema 替代重复说明
