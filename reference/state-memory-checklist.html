状态与记忆清单

Context 是视图，State 是工作台，Memory 是仓库。

首次建立 2026-10-27 配套 Lesson 0007 State · Compaction · Memory · Resume 可打印

长任务出问题，通常不是模型“忘了”，而是状态没有写下来、压缩丢了关键信息、 记忆没有写入策略，或者恢复后重复执行了副作用。这份清单把这几件事压成一页。

02State 设计检查

必须有的字段

  • messages（原始记录）
  • facts（key → value + source + confidence）
  • decisions / constraints
  • open questions
  • side effects（幂等键）
  • phase / turn / budget

事实与冲突

  • 每条事实都有来源，不能只有值
  • 同 key 新值覆盖旧值，旧值标记 superseded
  • 保留 fact history 以便审计
  • 来源不同置信度不同；冲突时按来源 + 置信度裁决

副作用

  • 写操作必须有幂等键（如 service + approval_id）
  • 执行前检查、执行后记录
  • 只读工具可重放；写工具不可重放
  • side effects 必须进 checkpoint

更新方式

  • 消息 append；事实按 key merge；问题去重
  • 不要让模型直接覆盖整个 state
  • 每次更新后 estimate tokens
  • 状态对象可序列化、可版本化

03Compaction 检查

压缩是有损的

“摘要看起来不错”不等于没丢信息。先最大化 recall（保留所有关键事实），再优化 precision（去掉噪音）。 对高风险任务，保留原始 trace 供审计，但不要把 trace 塞回上下文。

04Long-term memory 检查

类型存什么例子
Semantic事实、偏好、概念用户希望先看 runbook
Episodic过去的事件、动作序列上次连接池事故的处置
Procedural规则、流程、怎么做事回滚必须审批

写入策略

  • 显式“记住”优先；隐式提取要置信度阈值
  • 热路径写入（实时、可解释）vs 后台写入（不阻塞）
  • 去重；同一偏好不产生多条
  • TTL / 保留策略 / 删除接口
  • provenance、confidence、tags

读取策略

  • 相关性 + 时近性 + 重要性
  • 注入时带 memory ID 与来源
  • 记忆不是真值：冲突时让新证据覆盖
  • 检索不到时不要硬编；保持空
  • 权限与租户隔离
记忆投毒与隐私

记忆是跨会话的数据资产。攻击者可能通过一次对话写入恶意偏好；用户也可能不希望某些信息被长期保留。 写入前就要有来源、置信度、TTL 与删除策略，读取时不要把记忆当系统指令执行。

State 与事实冲突

def set_fact(state, key, value, source, confidence):
    old = state.facts.get(key)
    if old and old.value != value:
        old.status = "superseded"
        state.fact_history.append(old)
    state.facts[key] = Fact(key, value, source, confidence)

结构化压缩

summary = "\n".join([
