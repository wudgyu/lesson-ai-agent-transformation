三个最容易混淆的区别

Agent vs Workflow：控制流由谁决定。代码写死的是 workflow；模型每步自己决定的是 agent。

Tool calling vs Agent：工具调用只是一次能力扩展；Agent 是在循环里根据观察反复决定下一步。

RAG vs Memory：RAG 检索外部知识；Memory 保存这次/历次交互的状态与经验。两者都进上下文，但来源与生命周期不同。

A模型与推理

术语定义出现
大语言模型LLM在海量文本上训练、根据上下文预测下一个 token 的模型。它本身不执行工具、不访问网络、不记忆会话。W1
Token模型处理文本的最小单位，约等于一个词或词的一部分。计费、上下文长度、延迟都以它为单位。W1
上下文窗口context window模型单次调用能看到的 token 总量（输入 + 输出）。它是硬上限，也是成本与延迟的主要来源。W1
采样sampling模型从概率分布中选下一个 token 的方式。temperature、top_p 等参数控制随机性；Agent 任务通常需要低随机性。W1
结构化输出structured output让模型按 JSON Schema 等格式返回，便于程序解析。工具参数本质上也是结构化输出。W1
函数调用function calling / tool calling模型输出一个结构化的“我要调用某工具、参数是……”的请求；真正执行的是你的代码。W1 L1
上下文腐化context rot上下文越长，模型对其中信息的利用越差。不是“塞得越多越好”，需要裁剪、压缩与检索。W2

BAgent 架构

术语定义出现
Agent由模型动态决定下一步做什么、调用哪个工具、何时停止的系统。与 workflow 的关键区别是控制流归模型，不归代码。W1 L1
Agentic systemagentic systemAnthropic 的统称：包含 workflow 和 agent 两类。讨论架构时先分清你指的是哪一种。W1 L1
WorkflowLLM 与工具按预先写好的代码路径执行。可预测、易调试、成本低；适合步骤明确的业务。W1 L1
增强型 LLMaugmented LLM带检索、工具、记忆的 LLM，是构建 workflow 与 agent 的基础积木。W1 L1
ReActReasoning + Acting：模型交替产生“想法”和“动作”，执行动作后把观察结果喂回下一轮。现代 function calling 是它的工程化形态。W1 L1
工具tool暴露给模型调用的函数：有名字、描述、参数 schema 和返回值。工具设计是 Agent 工程的核心工作之一。W1 L1
Agent–Computer InterfaceACIAgent 与外部系统交互的接口设计，包括工具粒度、命名、参数、返回格式与错误信息。类比人机接口（HCI）。W1 D6
Agent 循环agent loop“模型决策 → 执行工具 → 观察结果 → 再决策”的循环，直到模型给出最终答案或触发停止条件。W1 L1
轨迹trajectory一次 Agent 运行中所有步骤的序列：模型输出、工具调用、观察、状态变化。评测与调试的基本单位。W1 L1
停止条件stop condition让循环结束的规则：模型给出最终答案、达到最大步数、超出预算、触发人工接管等。没有它就没有可靠的 Agent。W1 L1

C知识与记忆

术语定义出现
RAGRetrieval-Augmented Generation：先检索外部资料，再把相关资料放进上下文让模型回答。解决“模型不知道你的私有数据”。W1 L3
Embedding把文本映射成向量，使语义相近的文本在向量空间里距离更近。用于语义检索、聚类、去重。W1 L3
分块chunking把长文档切成适合检索与放入上下文的小块。块大小、重叠、按结构切分都会影响召回质量。W1 L3
混合检索hybrid search同时用关键词检索（BM25）与向量检索，再融合排序。对代码、专有名词、精确匹配尤其重要。W1 L3
BM25基于 TF-IDF 的关键词排序函数：罕见词权重高，词频收益会饱和，长文档会被惩罚。精确错误码、类名、配置键的主场。W1 L3
稠密检索dense retrieval用 embedding 向量做相似度检索，擅长同义改写与语义匹配；对精确标识符与否定不敏感。W1 L3
稀疏检索sparse retrieval以词项为维度的检索（如 BM25），每个文档只激活少量词项。与 dense retrieval 互补。W1 L3
倒数排名融合RRFReciprocal Rank Fusion：按 1/(k+rank) 累加多路排名。只看名次，避免不同检索器分数量纲不可比。W1 L3
Recall@ktop-k 结果中命中相关证据的比例。衡量“该找到的有没有找到”，是检索层最重要的下限指标。W1 L3
MRRMean Reciprocal Rank：第一条相关结果排名的倒数，按查询平均。衡量第一条结果靠不靠谱。W1 L3
上下文检索contextual retrieval在 embedding/BM25 之前，为每个 chunk 补一段 50–100 token 的情境说明，避免 chunk 脱离原文后失去指代。W1 L3
父子检索parent-child / small-to-big用小子块做精确检索，命中原文档后返回其父段落或相邻块，兼顾召回精度与生成所需上下文。W1 L3
重排reranking先用便宜的方法召回一批候选，再用更贵的模型对候选精排。提升精度，控制成本。W1 L4
双塔编码器bi-encoderquery 与 document 分别编码成向量，再用相似度检索。快、可离线建索引，但压缩会丢信息。W1 L4
交叉编码器cross-encoder把 query 与 document 拼在一起过模型，直接输出相关性分数。更准、更慢，通常用于第二阶段重排。W1 L4
引用citation把答案中的结论绑定到具体来源（文档、chunk、span）。让结论可验证、可审计，而不只是“看起来有出处”。W1 L4
引用精确率 / 召回率citation precision / recallprecision：给出的引用中真正支持结论的比例；recall：期望来源中被有效引用的比例。分别抓“乱引”和“漏引”。W1 L4
有据性groundedness / faithfulness答案中的 claim 是否能由检索到的上下文支持。Faithfulness 常按“被支持的 claim / 总 claim”计算。W1 L4
拒答abstention证据不足时明确说“不知道/证据不足”，而不是硬答。是 RAG 系统可信度的一部分，需要单独评测。W1 L4
缺失内容missing contentRAG 失败点 FP1：问题所需的信息不在语料里，系统却仍然生成答案。正确行为是拒答或补数据。W1 L4
中间遗忘lost in the middle长上下文中，位于中间的信息更容易被模型忽略。重排后也要注意把最强证据放在开头或结尾。W1 L4
Agent 状态agent state一次任务/会话内 Agent 已知与正在做的事：消息、事实、决策、未解决问题、副作用记录。可序列化、可 checkpoint。W2 L5
短期记忆short-term memory线程/会话作用域的记忆，通常就是 state 里的消息与事实，随 checkpoint 持久化，会话结束后不再共享。W2 L5
长期记忆long-term memory跨会话、跨任务保留的信息，存在外部 store，按 namespace/key 组织，需要写入与检索策略。W2 L5
语义记忆semantic memory事实、偏好、概念。例如“这个用户希望先看 runbook”。W2 L5
情景记忆episodic memory过去的事件与动作序列。例如“上次连接池事故是怎么处理的”。W2 L5
程序记忆procedural memory规则、流程、怎么做事。例如“回滚必须 on-call 负责人审批”。W2 L5
结构化笔记structured note-taking把进展写到上下文外的笔记（如 NOTES.md），需要时再读回上下文。适合跨很多步、有清晰里程碑的任务。W2 L5
上下文污染context pollution长上下文中的四类问题：poisoning（错误信息被沿用）、distraction（被长文带偏）、confusion（无关内容影响回答）、clash（上下文互相矛盾）。W2 L5
记忆memory跨轮次保留的信息。短期记忆通常是会话消息；长期记忆是外部存储的笔记、偏好、经验。W2 L5
压缩compaction上下文接近上限时，把历史总结成更短的状态并重新开始，保留关键决策与未解决问题。是有损的状态转移，不是人类摘要。W2 L5
子 Agentsub-agent由主 Agent 派生的专用 Agent，独立探索大量信息后只返回精简结论，用于突破上下文与并行探索的限制。W2 D11

D编排与协议

术语定义出现
状态图StateGraphLangGraph 的核心抽象：节点是计算步骤，边是控制流，状态在各节点间传递并按 reducer 合并。W2 D9
Reducer定义“新值如何合并进旧状态”的函数。例如消息列表用 append，计数器用求和。写错 reducer 是状态丢失的常见原因。W2 D9
检查点checkpoint把 Agent 每一步的状态持久化。支持断点恢复、时间旅行调试、多会话隔离。W2 L5
持久化执行durable execution进程崩溃或人工暂停后，任务能从上次检查点继续，且不重复执行有副作用的操作。W2 D13
幂等idempotency同一操作重复执行，效果与执行一次相同。Agent 重试、断点恢复、模型重复调用时，写工具必须幂等。W1 L2 · W2 L5
人在回路human-in-the-loop在关键动作前暂停，等待人类批准、修改或补充信息。高风险工具（转账、重启、删除）的默认配置。W2 D13
交接handoff一个 Agent 把控制权连同上下文交给另一个 Agent。OpenAI Agents SDK 的核心多 Agent 原语。W2 D11
Supervisor一个负责分派任务、汇总结果的协调 Agent；子 Agent 各自专注一个领域。比“全知全能单 Agent”更可控。W2 D11
MCPModel Context Protocol：把工具、资源、提示词以标准协议暴露给任意 Agent 客户端。2026-07 版本转向无状态核心。W2 D12
沙箱sandbox限制工具可访问的文件、网络、进程与权限的隔离环境。执行模型生成的代码或命令时必须使用。W3 D18

E评测与生产

术语定义出现
评测eval用一组可重复的任务与标准，衡量 Agent 的表现。没有评测，改进只能靠感觉。W1 D2
工具选择准确率tool-selection accuracyAgent 第一步是否选中了合适工具的比例。衡量工具命名、描述与粒度是否清晰的核心指标。W1 D6
黄金集golden set人工确认过期望输出的评测样本。应覆盖正常、边界、对抗与“应该拒答”的情况。W3 D15
LLM-as-judge用另一个模型按 rubric 给输出打分。便宜、可扩展，但需要校准，避免位置偏差与自我偏好。W3 D15
pass^k同一任务重复 k 次全部成功的概率，衡量可靠性而非“试几次总能对”。生产系统更关心 pass^k。W3 D16
Trace一次请求的完整调用链：每步的输入、输出、工具、耗时、token、错误。Agent 调试的第一现场。W1 L1
可观测性observability通过日志、指标、trace 回答“系统现在发生了什么、为什么”。Agent 的非确定性让它比传统服务更重要。W3 D17
护栏guardrail在输入、输出或工具调用前后执行的校验与限制，用于拦截不安全内容、越权操作与格式错误。W2/W3
最小权限least privilege只给 Agent 完成任务所需的最小工具与数据权限。写操作应默认拒绝，审批后放行。W1 D6
提示词注入prompt injection攻击者把恶意指令藏在网页、文档、工具返回中，诱导 Agent 偏离原任务或泄露信息。Agent 安全的核心威胁。W3 D18
Token 预算token budget为单次任务设定的 token/成本上限。Agent 循环会放大成本，必须在设计时就设预算与降级策略。W3 D17
