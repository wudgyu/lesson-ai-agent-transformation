六个最容易混淆的区别

Agent vs Workflow：控制流由谁决定。代码写死的是 workflow；模型每步自己决定的是 agent。

Tool calling vs Agent：工具调用只是一次能力扩展；Agent 是在循环里根据观察反复决定下一步。

RAG vs Memory：RAG 检索外部知识；Memory 保存这次/历次交互的状态与经验。两者都进上下文，但来源与生命周期不同。

Supervisor vs Handoff：控制权是否转移。Supervisor 保持控制、接收摘要；Handoff 把控制权交给 specialist，通常共享会话历史。

MCP vs Function calling：MCP 是工具提供方与消费方之间的协议；function calling 是模型输出“调用哪个工具”的格式。二者常串联，不互相替代。

Eval vs Benchmark：benchmark 衡量别人的分布，通常用于模型对比；eval 衡量你的用户真正会遇到的分布，用于产品决策。前者可以刷分，后者必须能指导改动。

A模型与推理

术语定义出现
大语言模型LLM在海量文本上训练、根据上下文预测下一个 token 的模型。它本身不执行工具、不访问网络、不记忆会话。W1 L1
Token模型处理文本的最小单位，约等于一个词或词的一部分。计费、上下文长度、延迟都以它为单位。W1 L1
上下文窗口context window模型单次调用能看到的 token 总量（输入 + 输出）。它是硬上限，也是成本与延迟的主要来源。W1 L1
采样sampling模型从概率分布中选下一个 token 的方式。temperature、top_p 等参数控制随机性；Agent 任务通常需要低随机性。W1 L1
结构化输出structured output让模型按 JSON Schema 等格式返回，便于程序解析。工具参数本质上也是结构化输出。W1 L1
函数调用function calling / tool calling模型输出一个结构化的“我要调用某工具、参数是……”的请求；真正执行的是你的代码。W1 L1 · L3
温度temperature缩放 logits 的采样参数：越低越接近最高概率，越高越随机。0 只降低随机性，不保证绝对确定。W1 L1
核采样top_p只保留累计概率最高的一部分 token 再采样。与 temperature 都会改变分布形状，不要同时盲调。W1 L1
JSON Schema描述 JSON 结构、类型、枚举、必填字段的契约。用于结构化输出、工具参数与校验。W1 L1
流式响应streaming模型把输出拆成增量 delta 返回，最后给完整文本与 usage。改善首 token 延迟，不改变总 token 成本。W1 L1
修复循环repair loop结构化输出校验失败时，把错误反馈给模型并重试有限次数；仍失败则降级或转人工。W1 L1
上下文工程context engineering决定这次调用看到哪些信息、以什么结构/顺序呈现：指令、证据、示例、契约、边界与预算。包含 prompt engineering。W1 L2
System prompt系统级指令：角色、目标、约束、输出契约、工具策略与数据边界。用户输入不应拼进 system。W1 L2
少样本示例few-shot在 prompt 中给出若干输入/输出示例，主要教格式、边界与标签口径，不是可靠的知识注入。W1 L2
输出契约output contract对输出结构、类型、枚举、必填与拒答行为的明确约定；必须由代码校验，而不只是 prompt 建议。W1 L2
上下文腐化context rot上下文越长，模型对其中信息的利用越差。不是“塞得越多越好”，需要裁剪、压缩与检索。W1 L2 · W1 L5

BAgent 架构

术语定义出现
Agent由模型动态决定下一步做什么、调用哪个工具、何时停止的系统。与 workflow 的关键区别是控制流归模型，不归代码。W1 L3
Agentic systemagentic systemAnthropic 的统称：包含 workflow 和 agent 两类。讨论架构时先分清你指的是哪一种。W1 L3
WorkflowLLM 与工具按预先写好的代码路径执行。可预测、易调试、成本低；适合步骤明确的业务。W1 L3
增强型 LLMaugmented LLM带检索、工具、记忆的 LLM，是构建 workflow 与 agent 的基础积木。W1 L3
ReActReasoning + Acting：模型交替产生“想法”和“动作”，执行动作后把观察结果喂回下一轮。现代 function calling 是它的工程化形态。W1 L3
工具tool暴露给模型调用的函数：有名字、描述、参数 schema 和返回值。工具设计是 Agent 工程的核心工作之一。W1 L3
Agent–Computer InterfaceACIAgent 与外部系统交互的接口设计，包括工具粒度、命名、参数、返回格式与错误信息。类比人机接口（HCI）。W1 L4
Agent 循环agent loop“模型决策 → 执行工具 → 观察结果 → 再决策”的循环，直到模型给出最终答案或触发停止条件。W1 L3
轨迹trajectory一次 Agent 运行中所有步骤的序列：模型输出、工具调用、观察、状态变化。评测与调试的基本单位。W1 L3
停止条件stop condition让循环结束的规则：模型给出最终答案、达到最大步数、超出预算、触发人工接管等。没有它就没有可靠的 Agent。W1 L3

C知识与记忆

术语定义出现
RAGRetrieval-Augmented Generation：先检索外部资料，再把相关资料放进上下文让模型回答。解决“模型不知道你的私有数据”。W1 L5
Embedding把文本映射成向量，使语义相近的文本在向量空间里距离更近。用于语义检索、聚类、去重。W1 L5
分块chunking把长文档切成适合检索与放入上下文的小块。块大小、重叠、按结构切分都会影响召回质量。W1 L5
混合检索hybrid search同时用关键词检索（BM25）与向量检索，再融合排序。对代码、专有名词、精确匹配尤其重要。W1 L5
BM25基于 TF-IDF 的关键词排序函数：罕见词权重高，词频收益会饱和，长文档会被惩罚。精确错误码、类名、配置键的主场。W1 L5
稠密检索dense retrieval用 embedding 向量做相似度检索，擅长同义改写与语义匹配；对精确标识符与否定不敏感。W1 L5
稀疏检索sparse retrieval以词项为维度的检索（如 BM25），每个文档只激活少量词项。与 dense retrieval 互补。W1 L5
倒数排名融合RRFReciprocal Rank Fusion：按 1/(k+rank) 累加多路排名。只看名次，避免不同检索器分数量纲不可比。W1 L5
Recall@ktop-k 结果中命中相关证据的比例。衡量“该找到的有没有找到”，是检索层最重要的下限指标。W1 L5
MRRMean Reciprocal Rank：第一条相关结果排名的倒数，按查询平均。衡量第一条结果靠不靠谱。W1 L5
上下文检索contextual retrieval在 embedding/BM25 之前，为每个 chunk 补一段 50–100 token 的情境说明，避免 chunk 脱离原文后失去指代。W1 L5
父子检索parent-child / small-to-big用小子块做精确检索，命中原文档后返回其父段落或相邻块，兼顾召回精度与生成所需上下文。W1 L5
重排reranking先用便宜的方法召回一批候选，再用更贵的模型对候选精排。提升精度，控制成本。W1 L6
双塔编码器bi-encoderquery 与 document 分别编码成向量，再用相似度检索。快、可离线建索引，但压缩会丢信息。W1 L6
交叉编码器cross-encoder把 query 与 document 拼在一起过模型，直接输出相关性分数。更准、更慢，通常用于第二阶段重排。W1 L6
引用citation把答案中的结论绑定到具体来源（文档、chunk、span）。让结论可验证、可审计，而不只是“看起来有出处”。W1 L6
引用精确率 / 召回率citation precision / recallprecision：给出的引用中真正支持结论的比例；recall：期望来源中被有效引用的比例。分别抓“乱引”和“漏引”。W1 L6
有据性groundedness / faithfulness答案中的 claim 是否能由检索到的上下文支持。Faithfulness 常按“被支持的 claim / 总 claim”计算。W1 L6
拒答abstention证据不足时明确说“不知道/证据不足”，而不是硬答。是 RAG 系统可信度的一部分，需要单独评测。W1 L6
缺失内容missing contentRAG 失败点 FP1：问题所需的信息不在语料里，系统却仍然生成答案。正确行为是拒答或补数据。W1 L6
中间遗忘lost in the middle长上下文中，位于中间的信息更容易被模型忽略。重排后也要注意把最强证据放在开头或结尾。W1 L6
Agent 状态agent state一次任务/会话内 Agent 已知与正在做的事：消息、事实、决策、未解决问题、副作用记录。可序列化、可 checkpoint。W2 L7
短期记忆short-term memory线程/会话作用域的记忆，通常就是 state 里的消息与事实，随 checkpoint 持久化，会话结束后不再共享。W2 L7
长期记忆long-term memory跨会话、跨任务保留的信息，存在外部 store，按 namespace/key 组织，需要写入与检索策略。W2 L7
语义记忆semantic memory事实、偏好、概念。例如“这个用户希望先看 runbook”。W2 L7
情景记忆episodic memory过去的事件与动作序列。例如“上次连接池事故是怎么处理的”。W2 L7
程序记忆procedural memory规则、流程、怎么做事。例如“回滚必须 on-call 负责人审批”。W2 L7
结构化笔记structured note-taking把进展写到上下文外的笔记（如 NOTES.md），需要时再读回上下文。适合跨很多步、有清晰里程碑的任务。W2 L7
上下文污染context pollution长上下文中的四类问题：poisoning（错误信息被沿用）、distraction（被长文带偏）、confusion（无关内容影响回答）、clash（上下文互相矛盾）。W2 L7
记忆memory跨轮次保留的信息。短期记忆通常是会话消息；长期记忆是外部存储的笔记、偏好、经验。W2 L7
压缩compaction上下文接近上限时，把历史总结成更短的状态并重新开始，保留关键决策与未解决问题。是有损的状态转移，不是人类摘要。W2 L7
子 Agentsub-agent由主 Agent 派生的专用 Agent，在独立上下文中探索大量信息后只返回精简结论，用于突破上下文与并行探索的限制。它是一种实现单元，不是控制拓扑。W2 D11
专家 Agentspecialist在多 Agent 系统里承担某个领域或阶段的专用 Agent；可以是 supervisor 的 worker，也可以是 handoff 的接收方。它描述职责，不描述控制权。W2 D11
上下文隔离context isolation让子 Agent 在自己的上下文窗口里工作，只把摘要与证据带回主线程。它降低主上下文的注意力压力，但增加总 token，并可能丢掉父级的隐含决策。W2 D11
委派契约delegation contract父 Agent 给子 Agent 的任务接口：目标、输入、已确认约束、可用工具、输出 schema、预算与停止条件。缺契约就会重复、遗漏或冲突。W2 D11

D编排与协议

术语定义出现
状态图StateGraphLangGraph 的核心抽象：节点是计算步骤，边是控制流，状态在各节点间传递并按 reducer 合并。W2 D9
Reducer定义“新值如何合并进旧状态”的函数。例如消息列表用 append，计数器用求和。写错 reducer 是状态丢失的常见原因。W2 D9
通道channelLangGraph state schema 里的一个字段。每个通道有自己的合并语义：默认覆盖，或由 reducer 决定 append / 求和 / 按 key 合并。W2 D9
超级步super-step图的一次调度轮次：当前可执行的节点一起运行，它们的增量按 reducer 合并，然后决定下一轮节点。checkpoint 与 recursion_limit 都以它为粒度。W2 D9
条件边conditional edge由路由函数根据当前 state 选择下一个节点的边。路由函数返回节点名或 END；映射表可把业务返回值翻译成节点名。W2 D9
递归上限recursion_limitLangGraph 对一次运行中 super-step 数的硬上限，超过时抛 GraphRecursionError。它是防失控的框架层兜底，不是业务预算。W2 D9
CommandLangGraph 中把状态更新与下一步路由合并到节点返回值的写法：Command(update=..., goto=...)。适合把控制流内聚在节点里。W2 D9
检查点checkpoint把 Agent 每一步的状态持久化。支持断点恢复、时间旅行调试、多会话隔离。W2 L7 · L9
检查点存储checkpointer按 thread 保存图状态快照的组件：InMemorySaver、SqliteSaver、PostgresSaver。它在 super-step 边界写入，不是每行代码都写。W2 L9
线程 IDthread_id一条 checkpoint 时间线的恢复键。resume 必须使用同一个 thread_id；换新 ID 等于开一条全新的时间线。W2 L9
中断interruptLangGraph 的持久化暂停原语：在节点内调用后保存 checkpoint 并把控制权交还调用方；恢复时节点从头重跑，resume 值成为它的返回值。W2 L9
恢复resume用 Command(resume=...) 与同一个 thread_id 继续一个暂停的图。已完成节点不重跑；未完成节点整段重跑。W2 L9
持久化级别durabilitycheckpoint 的写盘时机：sync 下一步前同步写、async 异步写（默认）、exit 只在退出时写。级别越高，崩溃窗口越小。W2 L9
流模式stream_modegraph.stream() 的事件粒度：values 快照、updates 节点增量、messages token、custom 业务事件、debug / checkpoints 运行时细节。W2 L9
时间旅行time travel用 get_state_history 查看旧 checkpoint，用 update_state 从旧点分叉重放。用于调试与复盘，不是生产回滚。W2 L9
持久化执行durable execution进程崩溃或人工暂停后，任务能从上次检查点继续，且不重复执行有副作用的操作。W2 L9 · L12
幂等idempotency同一操作重复执行，效果与执行一次相同。Agent 重试、断点恢复、模型重复调用时，写工具必须幂等。W1 L4 · W2 L7 · L9
人在回路human-in-the-loop在关键动作前暂停，等待人类批准、修改或补充信息。高风险工具（转账、重启、删除）的默认配置。W2 L9 · L12
审批疲劳approval fatigue审批请求过多导致人机械点击通过，gate 退化为橡皮图章。典型信号：通过率接近 100%、中位决策时间只有一两秒。W2 L12
自动化偏差automation bias人过度依赖系统输出、减少独立判断的倾向，在时间压力下更明显。EU AI Act 第 14 条要求在设计上防范。W2 L12
审批请求approval request绑定具体动作、证据、风险等级、发起人、有效期与所需批准数的状态对象；不是一条通知，而是可审计的实体。W2 L12
审批卡approval card审批请求的呈现形态：动作、目标、证据、后果、回滚、风险、发起人与有效期；决定审批人能否做出判断。W2 L12
动作指纹action digest工具名 + 规范化参数 + 发起人 + 任务号的哈希。审批绑定它，执行前重算并比较；防逻辑替换，不是密码学签名。W2 L12
双人复核four-eyes两位不同的、有授权的、非发起人分别批准同一动作。用于资金、不可逆或高影响动作，不等于“同一人点两次”。W2 L12
职责分离separation of duties发起人不能批准自己的请求；审批权与执行权分开，降低单点错误与舞弊风险。W2 L12
紧急通道break-glass显式绕过常规审批的应急路径：必须记录原因、双人确认或事后复核，并产生高优先级审计；不是隐藏的 --force。W2 L12
策略引擎policy engine按动作实例（工具 + 参数 + 上下文）决定自动/通知/审批/双人复核/拒绝的规则系统；未知动作默认拒绝。W2 L12
检查后使用竞态TOCTOUTime-of-check to time-of-use：检查时安全，不代表使用时安全。执行前必须重新评估策略、时效与目标状态。W2 L12
审批 SLA从请求到决定的时间窗口。必须服从事故 SLA；超时默认拒绝，不能让审批窗口把事故处置拖过时限。W2 L12
交接handoff一个 Agent 把控制权连同选定上下文交给另一个 Agent；接收方可以直接面对用户，也可以继续转交。与 supervisor 的关键区别是控制权转移。W2 D11
Supervisor保持控制权的协调 Agent：把子任务作为受控工具/子图调用，只接收摘要与证据，再自己汇总回答。与 handoff 的关键区别是控制权不转移。W2 D11
编排者-工作者orchestrator-workerAnthropic 对 supervisor 模式的称呼：lead 规划并分派，worker 在独立上下文里执行，返回精简结论；lead 决定是否追加 worker。W2 D11
路由器router无状态分类器：把请求路由给一个或多个 specialist，再合并输出。它不做多跳委派，也不维护对话状态。W2 D11
MASTMulti-Agent System Failure Taxonomy：14 种失败模式，分属系统设计、agent 间错位、任务验证三类；用于系统化诊断多 Agent 失败。W2 D11 · W3
MCPModel Context Protocol：基于 JSON-RPC 的开放协议，让 host 通过 1:1 client 发现并调用 server 的 tools、resources、prompts。2026-07-28 起为无状态核心。W2 D12
JSON-RPC 2.0JSON-RPC用 JSON 消息表示请求、响应与通知的远程调用格式。MCP 用它承载 server/discover、tools/list、tools/call 等方法。W2 D12
MCP host用户面对的应用程序：创建并管理多个 client，执行权限、同意与上下文聚合。Host 是安全策略的真正执行者。W2 D12
MCP clientHost 内与一个 server 一对一连接的协议端点；负责路由消息、管理订阅、维护 server 之间的安全边界。W2 D12
MCP server暴露 tools、resources、prompts 的本地进程或远程服务；只看到发给自己的请求，不拥有整段对话。W2 D12
MCP toolModel-controlled 的能力：有 name、description、inputSchema、可选 outputSchema 与 annotations；通过 tools/list 发现、tools/call 调用。W2 D12
MCP resourceApplication-driven 的可寻址数据，用 URI 标识；通过 resources/list 与 resources/read 访问，适合文档、代码、配置。W2 D12
MCP promptUser-controlled 的模板：通过 prompts/list 发现、prompts/get 渲染；参数是字符串，是否使用由用户决定。W2 D12
MCP transportstdio（本地子进程，JSON-RPC 走 stdin/stdout）或 Streamable HTTP（远程，POST /mcp）；HTTP+SSE 已弃用。W2 D12
server/discover2026-07-28 中 server 必须实现的 RPC：返回支持的协议版本、capabilities 与身份；client 可用它做版本选择或兼容探测。W2 D12
无状态协议stateless protocol每个请求自带协议版本、客户端信息与能力（_meta），不依赖连接或 session；跨调用状态用显式 handle。W2 D12
工具投毒tool poisoning把恶意指令写进工具描述、schema 或结果，诱导模型偏离任务或调用危险工具；缓解是可信 server 注册、投影、审批与描述审计。W2 D12 · W3 L16
沙箱sandbox限制工具可访问的文件、网络、进程与权限的隔离环境。执行模型生成的代码或命令时必须使用；文件隔离与网络隔离要同时生效。W3 L16

E评测与生产

术语定义出现
评测eval用一组可重复的任务与标准，衡量 Agent 的表现。没有评测，改进只能靠感觉。W1 L2
工具选择准确率tool-selection accuracyAgent 第一步是否选中了合适工具的比例。衡量工具命名、描述与粒度是否清晰的核心指标。W1 L4
黄金集golden set人工确认过期望输出的评测样本。应覆盖正常、边界、对抗与“应该拒答”的情况。W3 D15
评分标准rubric把“好答案”拆成原子、可观察、可独立判定的维度；每个维度用 PASS/FAIL/UNKNOWN，而不是 1–5 分整体印象。W3 L13
评分器grader真正执行判定的组件：代码断言、LLM judge 或人工评审。优先用代码判硬契约，再用模型判开放式质量。W3 L13
能力评测capability eval问“Agent 能做什么”：从低通过率开始，专门找弱点，是待爬的山。适合新功能与新模型。W3 L13
回归评测regression eval问“以前能做的现在还会吗”：应接近 100%，防止改动把已有能力弄坏。能力评测成熟后可毕业为回归评测。W3 L13
留出集holdout set不参与 prompt/rubric 调整的评测样本。用来估计真实泛化，防止针对测试集过拟合。W3 L13
错误分析error analysis读失败 trace、按根因聚类、再把失败写成 case 的过程。它决定评测集长什么样，比堆指标更重要。W3 L13
LLM-as-judge用另一个模型按 rubric 给输出打分。便宜、可扩展，但需要校准，避免位置偏差与自我偏好。W3 D15
Judge 校准judge calibration把 judge 当二分类器，用人工标签测 TPR/TNR/agreement；低 TPR 是漏检，低 TNR 是误报。agreement 高不代表可用。W3 L13
位置偏差position bias成对比较时 judge 偏好某个位置（通常是第一个）。缓解：交换 A/B 跑两次、随机化、取平均或要求一致。W3 L13
长度偏差verbosity biasjudge 偏好更长的答案，即使信息更少。缓解：rubric 写明长度不加分，用要点覆盖度替代字数。W3 L13
自我偏好self-enhancement biasjudge 偏好同家族模型的输出。缓解：用不同家族的 judge、多 judge 投票、人工校准。W3 L13
标准漂移criteria drift人需要标准才能评判输出，但看输出又会改变标准。评测集与 rubric 因此是迭代的，不是一次定死的。W3 L13
评测饱和eval saturation所有 case 都通过后，评测不再能区分好坏。需要加更难的 capability case，或把老 case 毕业成 regression。W3 L13
pass^k同一任务重复 k 次全部成功的概率，按 case 的 C(c,k)/C(n,k) 求平均估计，而不是把总体通过率做 k 次方。衡量可靠性，生产系统更关心它。W3 D16
pass@k同一任务重复 k 次至少成功一次的概率，随 k 上升。它衡量“多试几次能不能碰到”，不等于单次可靠性。W3 L13
轨迹评估trajectory eval对 Agent 运行过程中的工具选择、参数、顺序、审批、证据来源、预算等做判定。用于“路径本身就是需求”的安全、权限、流程与成本约束，默认仍应优先评 outcome。W3 L14
抖动率flake rate同一 case 在多次 trial 中既有成功又有失败的 case 比例。它区分“集中失败”（能力缺口）与“抖动失败”（可靠性问题），是 pass^k 的配套指标。W3 L14
发布门禁release gate一组分层的发布条件：完整性 fail closed；安全、回归、可靠性为硬约束；能力用配对检验；成本与抖动为软信号。输出 BLOCK / WARN / PASS，而不是一个总分。W3 L14
McNemar 检验McNemar test同一批 case 上比较两个版本的配对二分检验，只看“baseline 过、candidate 挂”和反向的 discordant pairs。比两个独立百分比更敏感。W3 L14
Trace一次请求的完整调用链，由 span 组成：每步的输入、输出、工具、耗时、token、错误。Agent 调试与评测的第一现场。W1 L3
SpanTrace 中一个有开始和结束时间的操作，例如一次模型调用、一次工具执行、一次 handoff。OpenTelemetry GenAI 约定用 invoke_agent / execute_tool 等 span 名。W3 L14
可观测性observability通过日志、指标、trace 回答“系统现在发生了什么、为什么”。Agent 的非确定性让它比传统服务更重要。W3 D17
Token 账本token ledger把每次 inference 的 usage 按 model 价格、cache 状态、失败/重试与业务维度记账。只从叶子 inference span 取数，避免 agent 汇总重复计费。W3 L15
单位成功成本cost per success总成本除以成功 run 数；分子包含失败调用与重试，分母只放成功任务。回答“做成一件要多少钱”，而不是“跑一次要多少钱”。W3 L15
关键路径critical path决定端到端时间的依赖链：父 → 子，顺序兄弟按时间连边，并行兄弟不连边。并行工具的总时长相加会高估墙钟。W3 L15
护栏guardrail在输入、输出或工具调用前后执行的校验与限制，用于拦截不安全内容、越权操作与格式错误。它是检测层，不是授权边界。W2/W3 · W3 L16
最小权限least privilege只给 Agent 完成任务所需的最小工具与数据权限。写操作应默认拒绝，审批后放行。W1 L4 · W3 L16
提示词注入prompt injection攻击者把恶意指令藏在用户输入、网页、文档或工具返回中，诱导 Agent 偏离原任务或泄露信息。分直接注入与间接注入；Agent 安全的核心威胁。W1 L2 · W3 L16
Token 预算token budget为单次任务设定的 token/成本上限。Agent 循环会放大成本，必须在设计时就设预算与降级策略。W1 L1 · W3 D17

F安全与权限

术语定义出现
间接提示词注入indirect prompt injection恶意指令不在用户输入里，而藏在 Agent 读取的网页、issue、日志、文档或工具结果中，诱导 Agent 把数据当指令执行。与直接注入相对。W3 L16
致命三要素lethal trifecta同时具备私有数据访问、不可信内容暴露、对外通信能力的 Agent；三者齐备时，注入可以把数据带出去。缓解是拆掉至少一条腿。W3 L16
二选三规则Agents Rule of TwoMeta 提出的设计启发式：单个 session 最多同时具备 A 处理不可信输入、B 访问敏感系统、C 改变状态或对外通信中的两项；三项都需要时，必须有人类监督或可靠验证。W3 L16
能力capability由可信任务/操作者授予的、对某个具体动作的权限，例如 fs:read:/repo、repo:write:feature/*。模型输出只能提议动作，不能自行扩大能力。W3 L16
来源provenance一个值从哪段上下文、哪个工具结果、哪个用户请求来。安全策略依据来源的信任等级决定它能否流向某个 sink。W3 L16
污点taint标记“这个值受不可信内容影响”。污点值流向 egress / exec 应拒绝，流向写操作应审批；这是信息流控制（IFC）的简化形式。W3 L16
信息流控制information-flow control用标签和策略约束数据在系统内的流动，而不只检查单个字符串。CaMeL 用控制流/数据流分离 + capability 实现可证明的注入抵抗。W3 L16
完全中介complete mediation每一次访问、每一个工具调用都在边界上重新检查授权，不能依赖模型“记住”规则。授权必须在 downstream 系统执行。W3 L16
参考监视器reference monitor在主体与客体之间强制执行访问控制的抽象机制：不可绕过、可验证、可审计。本课 gateway 的 policy 就是简化版。W3 L16
出口控制egress control限制 Agent 能连接的目标：域名 allowlist、HTTPS、端口、IP 段、重定向复查、DNS 与图片 URL。只限制输入不限制出口，等于没防外泄。W3 L16
混淆代理confused deputyAgent 用自己的高权限替低权限用户执行动作。防线是按用户身份与任务范围授权，而不是只信任 Agent 进程的权限。W3 L16
最小代理least agencyOWASP Agentic 2026 的原则：只给完成任务所需的最小自主性、工具与权限；高风险动作需要人类批准或结构化验证。W3 L16
自适应攻击adaptive attack攻击者针对具体防线迭代调整策略。研究表明多数静态防御在自适应攻击下 ASR 超过 90%，因此安全评测必须包含自适应红队。W3 L16
攻击成功率attack success rate (ASR)攻击样本中造成实际危害的比例。必须与 utility、误杀率、审批摩擦一起报，单独的 ASR 可以被“全部拒绝”刷低。W3 L16
效用保留utility retention加固后正常任务仍能完成的比例。安全门禁应同时约束 ASR 与 utility，避免把 Agent 变成只会拒绝的盒子。W3 L16
秘密脱敏secret redaction在工具输出进入模型上下文、日志或审计之前替换密钥、token、私钥等敏感值。脱敏是防线，不是加密，也不替代出口控制。W3 L16

G服务化与可靠性

术语定义出现
Run一次 Agent 执行的服务端对象，有自己的 id、状态机、事件日志、checkpoint 与最终结果。它比 HTTP 请求活得久，可跨重连甚至跨进程重启。W3 L17
事件日志event log按单调递增 seq 追加的 run 事件序列，例如 queued / started / phase_started / done。它是 SSE 的数据源，不是最终结果的唯一存储。W3 L17
Server-Sent EventsSSE基于 HTTP 的单向文本事件流，媒体类型为 text/event-stream；支持 id、event、data、retry 字段与浏览器自动重连。适合 Agent 进度与 token 流。W3 L17
Last-Event-IDSSE 重连时浏览器自动携带的请求头，值为最后收到的事件 id。服务端据此只发送该 id 之后的事件；若 id 已被淘汰，应先发 snapshot。W3 L17
快照snapshot事件日志发生 replay gap 时发送的压缩状态，包含当前 status、结果、最后事件 id。它让客户端不必补齐已淘汰的历史事件。W3 L17
背压backpressure下游消费不过来时，系统限制上游生产速度的机制。SSE 没有应用层流控，服务端只能用有界订阅者队列，满了丢弃并断开，让客户端按 Last-Event-ID 重连。W3 L17
准入控制admission control在创建工作之前决定“接不接”的一组检查：身份、幂等、租户配额、并发与队列容量。拒绝要返回可行动的状态码与 Retry-After。W3 L17
令牌桶token bucket以固定速率补充 token、允许最多 capacity 个突发的限流器。Agent 服务通常还用它做重试预算与模型配额。W3 L17
并发限制concurrency limit限制同时进行的工作量，而不是每秒请求数。它保护 worker、连接池、内存与模型配额；对长 run 比 QPS 限制更贴近真实资源。W3 L17
负载丢弃load shedding过载时主动拒绝一部分流量，以保住整体可用性与高优先级请求。常见形式是有界队列满返回 503、按关键性分级、客户端自适应拒绝。W3 L17
幂等键Idempotency-Key客户端为一次逻辑操作生成的唯一值，服务端把 key 与 payload fingerprint 绑定，使 POST 重试不会创建第二个 run。同 key 不同 payload 应返回 422。W3 L17
重试预算retry budget用令牌桶限制重试总量：重试消耗 token、成功回补，桶空即 fail fast。它把“要不要重试”从每个调用者的局部决定变成系统级约束。W3 L17
全抖动full jitter退避延迟取 uniform(0, min(max_delay, base×2^retry))，把同时失败的一批客户端摊开，避免同步重试打满下游。W3 L17
截止时间deadline一次 run 的绝对结束时间，而不是每层重新计时的 timeout。每一层只拿 remaining 预算，防止嵌套调用把总时长叠成数倍。W3 L17
优雅关停graceful shutdown收到 SIGTERM 后先让 readiness 失败、拒绝新 work、在 grace period 内 drain；超时则取消 worker 并写 checkpoint，而不是等 SIGKILL 丢状态。W3 L17
就绪探针readiness回答“现在能接新流量吗”。关停一开始就应为 false，让负载均衡器停止导流；它不是 liveness，不应检查下游依赖是否永久健康。W3 L17
存活探针liveness回答“进程是否还活着”。只有死锁或永久卡死才应失败；在下游故障时把 liveness 打挂会引发无意义的重启风暴。W3 L17
副作用账本effect ledger记录已经执行过的副作用，键通常是 (run_id, phase)。崩溃后重放时先查账本，避免重复发评论、重复开 PR；配合“先写 effect 再写 checkpoint”实现 exactly-once effect。W3 L17
