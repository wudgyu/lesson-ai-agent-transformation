这一页不解释概念，只把一次 LLM 调用的工程检查点压成一页： 预算够不够、采样合不合适、输出有没有契约、协议有没有配对。

01Token 预算检查

输入预算

  • system prompt 占多少？是否过长？
  • 对话历史是否随轮次无限增长？
  • 检索/工具结果是否过滤、截断、去重？
  • 是否给输出预留了足够 token？

输出预算

  • max_tokens 是否覆盖最坏情况？
  • finish_reason=length 是否被处理？
  • 流式输出是否仍然计入总 token？
  • usage 是否进了成本账本？

02采样参数

任务temperature备注
工具调用 / JSON 抽取0–0.3优先稳定与格式
事实问答 / 排障0.1–0.4可复现优先
头脑风暴 / 文案0.7–1.0需要多样性
要求确定性不要只靠 0用 schema、缓存、幂等、评测

temperature=0 不等于绝对确定；先固定 top_p，只调一个变量，用评测集验证。

04消息协议检查

消息检查点
system角色、约束、输出契约、工具使用规则；不要把用户输入拼进 system
user任务与输入分离；外部内容用分隔符包起来
assistant自然语言或 tool_calls；不要把 tool_calls 当执行结果
tool必须用 tool_call_id 与请求配对；错误也作为 tool 消息返回
finish_reasonstop / length / tool_calls / content_filter 分别处理
